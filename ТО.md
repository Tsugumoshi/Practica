# Регламент технического обслуживания (ТО)

## 1. Паспортная часть и общие положения

### 1.1 Назначение документа

Регламент определяет порядок, периодичность и содержание работ по техническому обслуживанию программного комплекса «Сумма чётных чисел Фибоначчи» (далее — ИС) с целью минимизации простоев, обеспечения безопасности данных и стабильности работы.

### 1.2 Область применения

Распространяется на:
- ПК разработчика (Windows 10/11, Python 3.10+);
- репозиторий GitHub;
- резервные копии данных ПО.

### 1.3 Роли участников

| Роль | Ответственность |
|------|-----------------|
| Инженер сопровождения | Выполнение планового и внепланового ТО |
| Администратор репозитория | Контроль версий, резервное копирование |
| Руководитель практики | Приёмка работ, контроль качества |

## 2. Технологические карты ТО

### 2.1 Плановое (профилактическое) ТО

| № | Операция | Периодичность | Алгоритм | Инструменты | Вид ТО |
|---|----------|---------------|----------|-------------|--------|
| 1 | Проверка свободного места на диске | Ежедневно | `df -h` / «Свойства диска» | ОС | Плановое |
| 2 | Проверка целостности репозитория | Еженедельно | `git fsck` | Git | Плановое |
| 3 | Резервное копирование данных | Ежедневно | Архивация каталога проекта (ZIP) | ОС / Python | Плановое |
| 4 | Проверка контрольных сумм SHA-256 | Еженедельно | Сверка манифеста резервной копии | Python | Плановое |
| 5 | Обновление зависимостей Python | Ежемесячно | `pip list --outdated` | pip | Плановое |
| 6 | Прогон тест-кейсов | Ежемесячно | Ручной прогон тестов | Python | Плановое |
| 7 | Проверка журналов ошибок | Ежедневно | Просмотр `stderr` | ОС | Плановое |
| 8 | Аудит прав доступа к репозиторию | Ежеквартально | GitHub Settings | GitHub | Плановое |
| 9 | Полная проверка системы | Ежегодно | Комплексный аудит | Все | Плановое |

### 2.2 Внеплановое (инцидентное) ТО

| № | Операция | Триггер | Алгоритм | Инструменты |
|---|----------|---------|----------|-------------|
| 1 | Восстановление из резервной копии | Повреждение данных | Распаковка ZIP-архива в каталог проекта | ОС |
| 2 | Откат версии | Критический баг | `git revert` | Git |
| 3 | Переустановка окружения | Сбой окружения | Переустановка Python 3.10+ | ОС |
| 4 | Анализ инцидента | Любой сбой | Фиксация в журнале, разбор причин | — |

## 3. Контроль качества и отчётность

### 3.1 Параметры контроля

- Время реакции на инцидент — не более 1 часа.
- Успешность резервного копирования — 100 %.
- Покрытие тестами ключевых модулей — не менее 90 %.
- Отсутствие критических ошибок в журнале — ежедневно.

### 3.2 Формы документов

- Журнал учёта выполненных работ ТО.
- Акт технического состояния.
- Отчёт о сбоях (по форме организации).
