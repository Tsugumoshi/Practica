# Техническое задание

**Программа «Сумма чётных чисел Фибоначчи»**

Версия документа: 1.2
Составлено по ГОСТ 19.201-78 (ЕСПД) с сокращением разделов для небольшой
консольной программы.

## 1. Общие сведения

1.1. Наименование программы: «Сумма чётных чисел Фибоначчи»
(`fibonacci_even_sum`).

1.2. Исполнитель: студент Абрамов И.С., группа ИСП-31с, специальность
09.02.07 «Информационные системы и программирование».

1.3. Основание для разработки: задание на учебную практику ПМ.06
«Сопровождение информационных систем», вариант 1, период 19.10.2026–31.10.2026.

1.4. Репозиторий проекта: <https://github.com/Tsugumoshi/Practica>.

## 2. Назначение разработки

Программа предназначена для вычисления суммы всех чётных элементов ряда
Фибоначчи (1, 2, 3, 5, 8, ...), которые не превышают значение, введённое
пользователем. Область применения — учебная, демонстрация процессов
сопровождения программного обеспечения: ввод/вывод данных, обработка
ошибок, резервное копирование, тестирование, документирование.

## 3. Требования к программе

### 3.1. Функциональные требования

Программа должна обеспечивать:

1. ввод значения: из консоли (интерактивный запрос с повтором при ошибке)
   или из файла, путь к которому передан в аргументе `--input`;
2. вывод результата: на экран всегда и дополнительно в файл, путь к
   которому передан в аргументе `--output`;
3. вычисление суммы чётных чисел Фибоначчи, не превышающих введённое
   значение; элемент, равный значению, учитывается;
4. допустимое входное значение — целое число не меньше нуля;
5. корректный результат при значении до 4 000 000 включительно
   (эталонный результат для 4 000 000 — 4 613 732);
6. строгий разбор ввода: строки вида «1_000» не принимаются как число.

### 3.2. Требования к надёжности

1. Некорректный ввод (пустая строка, текст, отрицательное число,
   отсутствующий или нечитаемый файл, закрытый ввод Ctrl+D/Ctrl+Z,
   недоступный каталог записи) не должен приводить к аварийному
   завершению с трассировкой; программа выводит понятное сообщение на
   русском языке и возвращает код завершения 1.
2. Кодирование сообщений об ошибках — на русском языке, с указанием
   имени файла, если ошибка связана с файлом.
3. Файлы, сохранённые в Блокноте Windows (кодировка UTF-8 с BOM),
   должны читаться корректно.

### 3.3. Требования к окружению

1. Интерпретатор Python версии 3.10 или выше.
2. Операционные системы: Windows, Linux, macOS.
3. Сторонние зависимости не требуются (только стандартная библиотека:
   argparse, re, sys, pathlib, zipfile, hashlib, datetime).

## 4. Сопутствующий модуль резервного копирования

Модуль `backup_restore.py` должен обеспечивать:

1. команду `backup` — полную копию каталога проекта в ZIP-архив с меткой
   времени в имени; служебные каталоги (`.git`, `__pycache__`,
   `.venv`, `backups`) в копию не включаются; существующий архив не
   перезаписывается;
2. манифест `manifest.sha256` внутри архива со строками
   «SHA-256-сумма путь» для каждого файла;
3. команду `verify` — проверку читаемости архива, совпадения состава
   файлов с манифестом и совпадения SHA-256 каждого файла;
4. команду `restore` — восстановление только после успешной проверки;
   извлечение файлов за пределы каталога назначения запрещено; манифест
   не извлекается;
5. возвращаемые коды завершения: 0 — успех, 1 — ошибка.

## 5. Требования к программной документации

В состав документации входят и хранятся в репозитории вместе с кодом:

1. `README.md` — руководство пользователя на русском и английском
   языках;
2. `docs/ТЗ.md` — настоящее техническое задание;
3. `docs/Регламент_ТО.md` — регламент технического обслуживания;
4. `docs/Тест-кейсы.md` — перечень тест-кейсов (не менее пяти на каждую
   функцию), оформленных по единой структуре: номер, предусловия, шаги,
   ожидаемый результат, фактический результат, статус.

## 7. Порядок контроля и приёмки

Программа считается принятой, если:

1. все автоматические тесты (`python -m unittest discover -v`)
   завершаются успешно (не менее 51 теста);
2. код соответствует код-стайлу: `black --check src tests` не находит
   отклонений;
3. для значения 4 000 000 программа выдаёт результат 4 613 732;
4. при некорректном вводе программа не завершается трассировкой и
   возвращает код 1;
5. созданная копия проекта проходит проверку `verify`, а восстановленный
   каталог совпадает с исходным;
6. документация соответствует фактическому поведению программы.
